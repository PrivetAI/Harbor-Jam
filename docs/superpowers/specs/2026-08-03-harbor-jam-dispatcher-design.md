**Заменяет:** `2026-07-28-harbor-jam-throttle-design.md` (переделка слайдинг-паззла; работа остановлена на приёмочном гейте, 6 задач из 13)

## 1. Зачем

Текущий Harbor Jam — Rush Hour с морской обёрткой, упрощённый до тапа, после которого лодка сама уплывает за край. Это не оценка, а измерение: `tools/HarborForge/BASELINE.md`, 140 уровней, 70 000 прогонов на настоящем движке.

| Свойство | Измерено |
|---|---|
| Уровней, где `par == числу лодок` | 140 / 140 — ни одну лодку не надо двигать дважды, глубина поиска = 1 |
| Политика «тапай всё, что может выйти» берёт 3 звезды | 96.66 % прогонов |
| Лодок, выходящих с первого тапа | 777 / 1170 (66.4 %) |
| Тапов, не меняющих ничего | 247 / 1170 (21.1 %) |

Четыре из пяти заявленных механик (приливы, цепи, течения, паром) доказуемо инертны: генератор строил уровень, разбирая готовое решение, и отбрасывал любой сид, где механика могла бы помешать этому решению. Верификатор был фильтром, удаляющим сложность.

Приложение никогда не отправлялось в App Store: нет скриншотов, нет записи в `APP_DESCRIPTIONS.md`, версия 1.0 / build 1. Совместимость ломать можно свободно.

**Цель:** заменить жанр целиком — вместо пошагового слайдинг-паззла реалтайм-диспетчер порта, где противником является затор, и доказать глубину измерением до того, как приложение будет отдано на ревью.

## 3. Игра

### 3.1 Поле

Портрет, сверху вниз:

1. **HUD** — порт и номер смены, выручка, репутация, полоса прилива с прогнозом.
2. **Причальная стенка** — горизонтальный ряд из 8–12 швартовых слотов. У каждого слота своя `depth` (1–5) и `equipment` (`none` / `crane` / `conveyor` / `pipeline`).
3. **Акватория** — вода между стенкой и входом, фон карты (изобаты, роза ветров).
4. **Фарватер** — одна полоса по центру снизу вверх. Общий ресурс: одновременно в нём только одно судно, в любом направлении.
5. **Рейд** — очередь ожидающих судов, вместимость `roadsteadCapacity` (стартово 4).

### 3.2 Сущности

```
Ship
  id: Int
  length: Int          // 2...5 слотов
  draft: Int           // осадка, 1...5
  cargo: Cargo         // .container | .bulk | .liquid
  tons: Int            // выручка и время разгрузки
  patienceTicks: Int   // тикает только пока судно на рейде
  state: .waiting | .transitingIn | .berthed | .aground | .transitingOut | .served | .lost

Slot
  depth: Int           // 1...5
  equipment: Equipment // .none | .crane | .conveyor | .pipeline

Harbor
  slots: [Slot]
  channelTransitTicks: Int
  tideAmplitude: Int   // 0, 1 или 2
  tideStepTicks: Int
  roadsteadCapacity: Int
```

Соответствие груза оборудованию строгое и одно к одному: `container→crane`, `bulk→conveyor`, `liquid→pipeline`.

### 3.3 Время

Симуляция тикает фиксированно **20 Гц** (1 тик = 0.05 с). Все длительности — целые тики. Ни одна величина в модели не выражена в секундах и не зависит от реального времени кадра: это условие детерминизма, без которого headless-гейт из раздела 6 невозможен.

Рендер подписан на `@Published` состояние; анимации SwiftUI интерполируют между тиками.

### 3.4 Прилив

Уровень прилива — целое число, шагающее от `0` до `2·tideAmplitude` и обратно, один шаг каждые `tideStepTicks`. Смещение глубины `tideOffset = level − tideAmplitude`.

Эффективная глубина слота `i` в тик `t` = `slots[i].depth + tideOffset(t)`.

Треугольная волна выбрана вместо синуса намеренно: игрок должен уметь посчитать, сколько тиков осталось до перелома, а полоса прилива показывает и текущий уровень, и направление, и время до перелома. Это планирование, а не рулетка.

### 3.5 Правила

**Швартовка.** Судно можно поставить на слот `s`, если одновременно:
- `s + length ≤ slots.count`;
- все слоты `[s, s+length)` свободны;
- `min(эффективная глубина этих слотов) ≥ draft` **в момент назначения**;
- фарватер свободен.

Судно переходит в `transitingIn` на `channelTransitTicks` тиков, занимая фарватер, затем становится `berthed` и начинает разгрузку.

**Разгрузка.** `unloadTicks = tons · ticksPerTon(cargo) · (equipment соответствует ? 1 : 2.5)`. В целочисленной арифметике — умножение на `2` или `5` с делением на `2`. Разгрузка идёт и на мели.

**Посадка на мель.** Пока судно ошвартовано, если эффективная глубина под ним падает ниже осадки — судно переходит в `aground`. Разгрузка продолжается, но уйти оно не может до следующего подъёма воды, продолжая держать свои слоты. Это подпись игры: единственная механика, которая наказывает решение, принятое минуту назад.

**Отход.** Тап по судну в `berthed`, у которого `unloadRemaining == 0`, при свободном фарватере. Слоты освобождаются **в момент начала** отхода, фарватер занят `channelTransitTicks` тиков, затем судно `served`.

**Терпение и потери.** `patienceTicks` тикает только в состоянии `waiting`. Истекло — судно `lost`, репутация −1. Приход при полном рейде — судно `lost` немедленно, репутация −1. Репутация стартует с `3`; ноль — смена провалена.

Место на рейде освобождается в момент перехода судна в `transitingIn`, а не по прибытии к причалу: рейд — это очередь ожидания, а не сопровождение.

**Конец смены.** У смены фиксированное расписание прибытий, сгенерированное из сида. Смена заканчивается, когда каждое судно расписания перешло в `served` или `lost`. Таймера смены нет.

### 3.6 Управление — два глагола

- **Перетащить** карточку судна с рейда на участок стенки. Во время перетаскивания подсвечиваются все валидные позиции и выделяется та, куда судно встанет; невалидные подсвечиваются красным с причиной («мелко», «не влезает», «фарватер занят»).
- **Тапнуть** разгруженное судно у стенки — оно уходит.

Больше глаголов нет. Направление фарватера не переключается вручную: он занимается тем, кто в него вошёл, и решение игрока — *когда* тратить этот ресурс.

### 3.7 Счёт и звёзды

```
score = Σ(tons · rate(cargo)) по обслуженным судам
      + max(0, parTicks − actualTicks) · speedRate
```

`parTicks` для каждой смены запекается HarborForge как результат политики S (раздел 6). Скорость входит в счёт напрямую, потому что плохая упаковка стенки и небрежное расходование фарватера проявляются именно как затянувшаяся смена.

`rate(cargo)`, `ticksPerTon(cargo)` и `speedRate` — константы каталога, а не магические числа по месту. Их стартовые значения задаются в `HJShiftCatalog` и тюнингуются гейтом из раздела 6 наравне с параметрами портов.

- 1★ — смена завершена с репутацией > 0;
- 2★ — `score ≥ target2`;
- 3★ — `score ≥ target3`.

`target2` и `target3` не назначаются вручную, а калибруются HarborForge по политикам (раздел 6).

## 4. Содержание

### 4.1 Кампания: 7 портов × 12 смен = 84

Каждый порт вводит ровно одну новую вещь и не вводит ничего больше.

| # | Порт | Новое | Опорные параметры |
|---|---|---|---|
| 1 | Quiet Cove | длина, упаковка, очередь | 8 слотов, глубина 5 везде, `tideAmplitude 0`, канал 30 тиков, только контейнеры, везде кран |
| 2 | Tidewater Quay | осадка, прилив, посадка на мель | `tideAmplitude 1`, глубины слотов 2–5 |
| 3 | Narrow Channel | фарватер как дефицитный ресурс | канал 80 тиков |
| 4 | Mixed Berths | типы груза и оборудования | три типа, штраф ×2.5 за несоответствие |
| 5 | Storm Roads | события | слот на ремонте 200–400 тиков; шторм на 600 тиков даёт ×1.5 к расходу терпения |
| 6 | Deepwater Port | масштаб | 12 слотов, суда длиной 5, `tideAmplitude 2`, суда длиной ≥ 4 занимают фарватер ×1.5 |
| 7 | Grand Harbor | всё сразу + VIP | VIP-суда: терпение ×0.5, ставка ×3 |

Все числа в таблице — **стартовые**, подлежащие тюнингу гейтом из раздела 6. Ни одно из них не является требованием.

События порта 5 планируются расписанием смены из сида, а не бросаются случайно во время игры: headless-гейт обязан воспроизводить смену тик в тик.

Разблокировка: порт `n` (нумерация с 1) открывается при `20·(n−1)` суммарных звёзд — из 36 возможных за каждый порт. Смена `k+1` внутри порта открывается по хотя бы одной звезде на смене `k`.

### 4.2 Верфь (магазин)

Валюта — накопленная выручка. Пять глобальных линий:

| Линия | Уровни | Эффект уровня |
|---|---|---|
| Краны | 5 | −8 % времени разгрузки |
| Буксиры | 3 | −10 % времени прохода фарватера |
| Дноуглубление | 2 | +1 к глубине всех слотов |
| Рейд | 2 | +1 место (4 → 6) |
| Команда | 2 | +1 к стартовой репутации (3 → 5) |

Все эффекты глобальные — это сознательное упрощение: пер-слотовые апгрейды пришлось бы моделировать в headless-гейте отдельно для каждого порта.

Верфь — не вкладка, а пуш-экран с экрана порта, чтобы сохранить четырёхтабовую конвенцию портфеля.

### 4.3 Бесконечный режим «Вахта»

Одна гавань на 10 слотов. Расписание прибытий генерируется бесконечно с растущей интенсивностью. Каждые 1800 тиков (90 с) — выбор одного апгрейда из трёх; апгрейды действуют до конца забега и не тратят монеты кампании. Конец при нулевой репутации. Рекорд — обслуженный тоннаж.

### 4.4 Награды

Достижения переписываются под новые статистики: обслуженный тоннаж, суда без потерь, смены с тремя звёздами, лучшая Вахта, суда, снятые с мели, смены без единой посадки на мель. Старый набор (`boatsExited`, `totalTaps`, `winsWithoutUndo`, дейли-стрик) удаляется целиком.

## 5. Сохранение

Новый ключ `hbj.state.v3`. Старые `hbj.state.v1` не читаются и не мигрируются — приложение не релизилось, все прежние звёзды бессмысленны.

```
HJSaveState
  shiftRecords: [String: HJShiftRecord]   // "port-shift" -> stars, bestScore
  coins: Int
  upgrades: [String: Int]                 // линия -> уровень
  watchBestTons: Int
  stats: HJStats
  soundOn, hapticsOn, reduceMotion, onboardingSeen: Bool
```

**Каждое** поле в `init(from:)` декодируется через `decodeIfPresent(...) ?? default`. Добавление необязательного поля в `Codable`-структуру, лежащую в `UserDefaults`, уже однажды стирало весь прогресс в этом портфеле; синтезированный декодер бросает на отсутствующем ключе.

## 6. Приёмочный гейт — то, на чём игра провалилась в прошлый раз

`tools/HarborForge` переписывается под новую симуляцию и остаётся единственным критерием готовности. Он компилируется `swiftc` против **настоящих** исходников симуляции (они импортируют только Foundation) и гоняет три политики по всей кампании:

- **G — жадная.** Первое подходящее место; выпускать сразу, как разгрузилось.
- **R — случайная валидная.**
- **S — умная.** Best-fit по упаковке; проверка прогноза прилива перед постановкой глубокого судна; придержать отход, если на рейде есть судно с истекающим терпением, которому нужен фарватер.

**Гейт. Все пункты обязательны:**

1. Политика S завершает (≥1★) 84 из 84 смен.
2. Политика S берёт 3★ минимум на 80 % смен.
3. Политика G берёт 3★ **не более чем на 25 %** смен портов 3–7.
4. Политика G полностью проваливает (репутация 0) **минимум 30 %** смен портов 5–7.
5. Политика R не берёт 3★ ни на одной смене.
6. Медианный `score` политики S ≥ 1.35 × медианный `score` политики G по портам 3–7.
7. Механики доказуемо активны — по счётчикам симуляции на прогонах S: посадок на мель > 0 начиная с порта 2; отказов по причине «фарватер занят» > 0 начиная с порта 3; разгрузок с неподходящим оборудованием > 0 начиная с порта 4.

Пункты 3, 4 и 6 — прямая защита от повторения провала: они требуют, чтобы жадность **измеримо проигрывала**. Пункт 7 — защита от инертных механик: в прошлой игре четыре механики из пяти не влияли ни на что, и никто этого не заметил, пока не был написан harness.

`target2` / `target3` каждой смены калибруются так: `target3` = 92 % от `score` политики S, `target2` = 70 %. Значения запекаются вместе со сменами.

**Гейт — точка «стоп».** Если хоть один пункт не выполняется, тюнингуются параметры портов из таблицы 4.1, и гейт гоняется заново. Приложение при этом не трогается. Работа не продолжается «с тем, что есть».

Смены запекаются в `Harbor Jam/shifts.json` (расписание прибытий, гавань, `parTicks`, `target2`, `target3`). Приложение при старте смены прогоняет её через ту же симуляцию как проверку целостности.

### 7.3 Конвейер ассетов

Каждый спрайт кладётся как `Assets.xcassets/<name>.imageset/<name>.svg` плюс `Contents.json` с `"preserves-vector-representation": true` и универсальным `"single"`-скейлом. В pbxproj `Assets.xcassets` — ссылка на папку (`folder.assetcatalog`), поэтому **добавление спрайтов не требует правки проекта**.

Ограничения на SVG, которые переваривает `actool`: только `path`, `rect`, `circle`, `polygon`, заливка и обводка, простые трансформации. Никакого `<text>`, фильтров, масок, градиентов. Цифры осадки рисуются поверх обычным SwiftUI `Text` — это нужно и само по себе, потому что они динамические.

Работоспособность этого конвейера проверяется **первой же задачей плана**, на одном спрайте, сборкой и скриншотом с симулятора. Запасной путь, если `actool` откажется: скрипт `tools/HarborArt/render.swift` рисует те же формы через CoreGraphics в PNG @2x/@3x — путь, уже отработанный в портфеле на иконках приложений.

Никаких SF Symbols и никаких эмодзи, как и во всём портфеле.

Второй фазы Resources не создавать. Идентификаторы объектов назначаются по одному на файл и не переиспользуются. Проект не использует синхронизированные группы и xcodegen.

## 10. Технические ловушки, уже стоившие времени в этом портфеле

- **`.contentShape(Rectangle())` после `.position()`** превращает вид в тап-мишень размером с экран и съедает все элементы под ним. Порядок модификаторов на слоях поля критичен.
- **Замыкание `Canvas` получает свой `size`, а не размер экрана.** Любая геометрия карты считается от `screenSize`, переданного родителем.
- **Кнопка, у которой label — только фигура поверх `Color.clear`,** имеет нулевую площадь нажатия.
- **Фиксированная по ширине дочерняя вьюха обязана вычитать все вложенные отступы,** а не только внешний, иначе вылезает за правый край.
- **На iPad сырой `GeometryReader` в верхнем-левом углу рапортует ширину больше видимой** — обрезает контент справа (Guideline 4.0). Используется `HJLayout`.
- **iOS 15 учитывает только последний `.sheet` на вьюхе.**
- **Ссылочная модель, переданная в подвиджет, не перерисовывает его** при мутации внутреннего поля — в поле передаются значения, а не объекты.

## 11. Риски

| Риск | Реакция |
|---|---|
| `actool` не соберёт SVG | Проверяется первой задачей; фолбэк — PNG через CoreGraphics |
| Реалтайм на SwiftUI просаживает кадры при 20 судах | Симуляция на 20 Гц отделена от рендера; при просадке слои поля переносятся в один `Canvas` |
| Гейт не сходится тюнингом параметров | Пункты 3, 4, 6 гейта останавливают работу; при повторном несхождении режется одна из четырёх механик, а не смягчается гейт |
| Четыре ограничения перегружают игрока | Порты вводят строго по одному; онбординг в первой смене; в руководстве по странице на механику |

## 12. Не входит в объём

- Внутриигровые покупки, реклама, аналитика.
- Ежедневная смена (заказчик выбрал кампанию + бесконечный режим).
- Мультиплеер, Game Center, iCloud-синхронизация.
- Локализация — интерфейс английский, как во всём портфеле.
- Любые изменения WebView-гейта, домена и подписи.
